# Agent Notes

## Git workflow

- Changes are never pushed directly to `main`; always via a branch and a pull request.
- This also applies to small changes (fixes, docs, specs).
- Every pull request MUST reference its issue (e.g. "Closes #7") if one exists; if there is none, note that briefly in the PR.

## Project

Adventure Chess (German: Schach Abenteurer) is a kid-friendly chess puzzle app for ages 5 to 10. The interface is available in German, English and French; mobile-first (phone/tablet, portrait), with Knight Kuno as a companion.

- Puzzles come from the Lichess database (CC0), generated by `scripts/extract-puzzles.mjs`.
- `src/data/puzzles.json` is generated – do not edit it by hand.
- Design: use the existing tokens in `src/styles/tokens.css`; the art style is rounded cartoon SVGs with an ink outline (`--ink`).

## World checklist (every new world)

GitHub issues for new worlds often omit these items; they still belong in every spec, plan and task list:

- 12 curated puzzles in `puzzles.json` (via `scripts/extract-puzzles.mjs`).
- **Endless pool**: at least 50 further puzzles in `endless.<world>.json`, no duplicates of the curated set or earlier pools, plus the offline fallback message with a button back to the map.
- Name and subtitle in DE, EN, FR; own map art; Kuno task text.
- Handoff button from the previous world's chest; the previous world's end-of-map signpost loses its "soon" badge; the new world's preview points to the next one.
- Earlier worlds' puzzles and progress stay unchanged.

Use `specs/007-glutvulkan-pin-skewer/spec.md` as the reference for a complete world spec.

## Commands

- `npm run dev` – development server
- `npm run build` – typecheck + build; must pass at the end of every change
- `npm run puzzles` – re-fetch puzzles from the Lichess DB (requires `curl` and `zstd`)

## Structure

- `src/game/` – data and logic (worlds, progress, map geometry, sounds)
- `src/hooks/usePuzzle.ts` – the flow of one puzzle (opponent move, move checking, stars)
- `src/i18n/` – UI texts for German, English and French (dictionaries, `useI18n`)
- `src/components/` – screens and presentation
- `scripts/extract-puzzles.mjs` – puzzle generator; new worlds go at the top of `WORLDS`
- GitHub issues with label `roadmap` – the backlog of all planned ideas

## Spec Kit artifacts

Principle: only project intent is versioned; anything generated or installed by `specify init` is reconstructed after a clone.

- Versioned: the constitution (`.specify/memory/constitution.md`), `.specify/integration.json`, `.specify/init-options.json`, `.specify/extensions.yml`, `.specify/bundle.yml` (the pinned extension/preset stack), `.specify/extension-catalogs.yml` (catalog stack; makes the community catalog installable here), the extension configs `.specify/extensions/*/*-config.yml`, the project-local `reference` extension source in `tools/speckit-reference/`, plus the ignore rules in the root `.gitignore` (deliberately there instead of `.specify/.gitignore`, which `specify init --force` overwrites).
- Ignored: `.specify/scripts/`, `.specify/templates/`, `.specify/presets/`, `.specify/workflows/`, `.specify/feature.json`, `.specify/integrations/*.manifest.json` (install records with timestamps), `.specify/integrations/.cache/`, `.opencode/`, the generated Pi commands `.pi/prompts/speckit.*.md` (hand-written Pi prompts stay versioned) and `specs/`.
- Reconstruction after a fresh clone (the CLI version comes from `init-options.json`, currently 1.0.13):

  ```bash
  specify init --here --force --non-interactive --integration pi --script sh
  specify integration install opencode
  specify bundle install .specify/bundle.yml
  specify extension add --dev tools/speckit-reference
  ```

  Afterwards `git status` is clean. `bug` is pinned in the bundle to the CLI version (`init-options.json`), since it ships with the CLI. `wireframe` comes from the community catalog, which `.specify/extension-catalogs.yml` declares install-allowed. `reference` is a project-local extension installed from `tools/speckit-reference`.
